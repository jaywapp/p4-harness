# P4 코어와 작업 워크플로우의 경계

계획·수행·리뷰 흐름은 [jsonl-prr](https://github.com/jaywapp/jsonl-prr)에 정의합니다. `p4-harness`는 `p4.exe`를 이용한 파일 준비, numbered CL, 작업 범위와 실제 P4 상태 검증에 집중합니다. P4V와 CLI를 대체하지 않고, 에이전트가 같은 작업 절차를 따르게 하는 계층입니다.

| 책임 | 담당 |
|---|---|
| checkout, 새 파일 예약, P4 move/delete/collect | p4-harness |
| client/root 확인, have revision, CL action 확인 | p4-harness |
| 같은 작업의 CL, 작성자 인계, pending CL 보고 | p4-harness |
| JSONL 계획·ID 조회·사용자 의견 누적 | jsonl-prr |
| Claude 모델 배정·단계 스킬·독립성 판단 | jsonl-prr |
| Codex Luna max 리뷰·수정/반박·양측 합의 | jsonl-prr |

## 함께 사용할 때

전체 작업 하나를 P4 task 하나와 numbered CL 하나에 대응시킵니다. JSONL의 T01, T02 등은 그 작업 안의 하위 계획입니다. 하위 ID마다 `p4h begin`을 실행하거나 CL을 새로 만들지 않습니다.

1. 기존 설치/설정 변경은 일반 P4 절차로 파일을 준비한 뒤 처리합니다. 새 하네스의 `.prr` 실행 상태·blob·로그가 제품 소스에 섞이지 않도록 프로젝트의 기존 ignore/범위 정책을 적용합니다. `jsonl-prr`가 P4 설정을 수정하지는 않습니다.
2. 메인 Claude가 P4 `begin`으로 작업 CL을 시작하고 JSONL 계획을 초기화합니다. 코드 변경 전 두 작업 범위를 맞춥니다.
3. Claude가 수행하면서 기존 `prepare`/편집 훅/`collect` 절차를 따릅니다. 계획과 사용자 의견은 JSONL에 추가합니다.
4. 작성자가 멈춘 상태에서 P4 collect/required checks와 작업 흐름의 검증을 수행합니다. 각 하네스의 필수 검증 설정과 완료 조건을 실제 실행 결과로 충족해야 합니다. 양쪽에 같은 검사를 필수로 등록했다면 현재 버전에서는 각 검사를 실행합니다. 하네스 사이의 증거 자동 재사용은 제공하지 않습니다.
5. Codex는 읽기 전용 리뷰만 수행합니다. 리뷰 때문에 CL 소유권을 넘길 필요는 없습니다. 수정은 계속 Claude가 담당합니다. 기존 `handoff --to codex`는 Codex가 실제 작성자로 이어받을 때 사용하는 별도 기능입니다.
6. 리뷰 합의와 현재 파일 상태를 확인하고 각 하네스의 완료 보고를 생성합니다. P4 `finish`는 pending CL을 남깁니다. submit은 기존 절차를 따릅니다.

두 완료 명령은 분산 트랜잭션이 아닙니다. 그 사이에 코드를 수정하지 말고, 둘 중 하나라도 실패하면 전체 완료로 보고하지 않습니다. 한 하네스의 완료 기록을 다른 하네스의 검사 성공으로 위조해서 사용하지 않습니다.

## 병렬 범위

현재 P4 코어는 한 물리 workspace에 작성 작업/세션 하나를 전제로 합니다. JSONL에서 경로 독립성이 확인되었다고 이 제한이 없어지지는 않습니다. 함께 사용하는 현재 버전에서는 읽기·분석 서브에이전트를 병렬로 활용하고 파일 수정은 한 작성자가 순차 수행합니다.

동시에 수정하려고 세션 검사나 훅을 우회하지 않습니다. 별도 client/root의 동시 작성과 결과 통합은 별도 운영 절차이며, 이 버전은 자동 병렬 작성·통합을 제공하지 않습니다. 향후 같은 CL의 파일별 위임 기능을 추가한다면 P4 코어에서 독립적으로 검증해야 합니다. `jsonl-prr`에는 P4 전용 CL이나 위임 상태를 넣지 않습니다.

## 이번 정리의 완료 범위

P4 코어 0.2의 요약 출력, snapshot 이후 파일 선택, 실패 로그 선별, 짧은 인계 context, 필수 검사 일괄 실행을 유지합니다. 작업 계획 JSONL과 단계별 에이전트 조율은 새 저장소로 분리했습니다. 엔진별 기능은 추가하지 않았습니다.

기존 49개 테스트(실제 임시 P4/P4D 서버 통합 27개 포함)를 다시 실행해 통과했습니다. 실제 회사 서버와 로그인된 에이전트 CLI 동작은 해당 환경의 설치 검증 대상입니다.
